## 一、事实基线（源码确认，2026-07-22）

### OpenTalking 服务端（本地资产 `/Users/wangzhenyu/Desktop/ALLProject/opentalking/`）

- SSE 事件流：`GET {apiBase}/sessions/{session_id}/events`（`text/event-stream`，`apps/api/routes/events.py`）
- 事件 schema（`opentalking/core/types/events.py`，权威以本地代码为准）：
  | event | payload | 语义 |
  |---|---|---|
  | `speech.started` | `{session_id, text}` | 一轮播报开始 |
  | `subtitle.chunk` | `{session_id, text, is_final=false}` | 字幕分块（增量/累计语义执行时查 `synthesis_runner.py:2258/2608` 确认后实现，代码注释留依据） |
  | `speech.ended` | `{session_id, text?}` | 播报结束，text 为完整回复 |
  | `session.state_changed` | `{session_id, old_state, new_state}` | 会话状态迁移 |
  | `session.queued` | `{session_id, position, message}` | 排队（忽略即可） |
  | `error` | `{session_id, code, message}` | 错误 |
  | `ping` | `{}` | 保活（忽略） |
- 打断：`POST {apiBase}/sessions/{session_id}/interrupt`（`sessions.py:1304`）
- WebRTC 无 data channel（全仓 grep 无 `createDataChannel`）——字幕/状态只走 SSE。

### omni_voice 状态文件（M5.4，`omni-brain/plugins/omni_voice/state_file.py`）

- 路径 `~/.ai-omni/state/voice-status.json`，原子写（tmp + os.replace）
- 现 schema：`{state, running, fake_mode, ts}` —— **无 reply 字段**，需扩展
- 状态机取值：idle / wake_listening / recording / transcribing / thinking / speaking

## 二、联动链路

```
omni_voice 宿主管道
  └─ 进入 SPEAKING：state_file.write("speaking", reply=<本轮回复文本>)
  └─ 离开 SPEAKING：state_file.write(<new_state>)            # 不带 reply 字段
       └─ voice-status.json {state, running, fake_mode, ts, reply?}
            └─ Rust notify watcher（status.rs）解析 reply: Option<String> → Tauri 事件透传
                 └─ statusStore.voice.reply: string | null（TS）
                      └─ opentalkingBridge：backendId==="opentalking" 且
                          state 迁移到 speaking 且 reply 非空
                            └─ handle.speakText(reply) → OpenTalking 服务端 TTS
                                 → WebRTC 视频口型 + 发声（唯一发声源，omni_voice 配 tts_muted）
OpenTalking SSE（opentalkingClient 扩展，EventSource DI）
  ├─ subtitle.chunk      → subtitleStore → 相框底部字幕（显影渐显）
  ├─ speech.started      → 字幕清空、新 turn
  ├─ speech.ended        → 字幕收尾（final 停留渐隐）
  ├─ session.state_changed → 相框氛围（speaking 微光呼吸）
  └─ interrupt() 按钮     → POST /sessions/{id}/interrupt
```

## 三、各侧改动契约

### A. omni_voice（Python，TDD）

1. `state_file.py`：`VoiceStateFile.write(state, *, running, fake_mode, reply=None)`；
   `reply` 为 None 时 payload 不带该字段；为 str 时写入。`read` 解析放宽：
   reply 缺省/非字符串 → 不含 reply 键（或 None），既有 `{state,running,fake_mode,ts}` 校验不变。
2. `pipeline.py`：进入 SPEAKING 的写入点携带本轮回复文本；迁移到其他状态不携带。
   管道侧 `state_writer` 鸭子契约保持 `write(state, running)` 两参——reply 经
   `PipelineStateWriter` 新增可选方法或构造期适配，不破坏既有契约（执行时选最小侵入方案，
   代码注释说明）。
3. `config.py` + `pipeline.py`：新增 `tts_muted: bool = False`；为 True 时跳过 TTS 播放
   （不调用 TTS 后端 speak），但状态机照走 SPEAKING、reply 照写、事件照发。
   用途：OpenTalking 模式下 omni_voice 静音，由 OpenTalking 独家发声。
4. 测试：reply 写入/读取/缺省兼容、muted 跳过播放且状态照走、既有 382 测试零回归。

### B. Rust（omni-hud/src-tauri，cargo test）

1. voice-status 解析结构加 `reply: Option<String>`（serde default，缺字段兼容旧文件）。
2. `voice-status` Tauri 事件 payload 透传 reply；watcher 防抖/原子读行为不变。

### C. TS 前端（omni-hud/src，vitest，全 DI 可测）

1. `avatar/opentalkingClient.ts` 扩展：
   - `OpenTalkingClientDeps` 加可选 `createEventSource`（缺省浏览器原生 `EventSource`）。
   - connect 成功后订阅 `/sessions/{id}/events`；`close()` 时关闭 EventSource（在 pc.close 之前）。
   - `ConnectHooks` 加结构化回调：
     `onSubtitle?(text: string, isFinal: boolean)`、
     `onSpeechChange?(speaking: boolean)`、
     `onSessionState?(oldState: string, newState: string)`、
     `onStreamError?(code: string, message: string)`。
     未知事件/ping 忽略；JSON 解析失败的单条消息跳过不致命。
   - `OpenTalkingConnection` 加 `interrupt(): Promise<void>` → POST interrupt；HTTP 非 2xx 抛错。
2. `store/statusStore.ts` + `data/sources.ts` + `data/tauriSource.ts`：
   voice 通道状态加 `reply: string | null`；normalize 时缺省/非字符串 → null；
   fake source 同步支持构造 reply（测试用）。
3. `avatar/subtitleStore.ts`（新）：`{text, isFinal, visible}` 订阅模式（与 themeStore 同款）；
   speech.started → 清空+visible；chunk → 按确认后的增量/累计语义更新；
   speech.ended → isFinal=true，停留后渐隐（visible=false 由 UI 计时器或 ended 直控，
   执行时定并注释）；`prefers-reduced-motion` 下无渐隐动画直接显隐。
4. `avatar/opentalkingBridge.ts`（新）：deps `{statusStore, backendStore, getHandle}`。
   订阅 statusStore：`voice.state` 迁移到 `"speaking"` 且 `reply` 非空且
   `backendStore.getState().backendId === "opentalking"` → `getHandle()?.speakText(reply)`。
   去重：同一 reply 文本同一 speaking 边沿只发一次；speakText 失败静默（HUD 不容崩溃）；
   后端非 opentalking 或 handle 未就绪 → 跳过（Live2D 路径由 speakingDriver 照旧）。
   返回 dispose。App.tsx 挂载/卸载接线。
5. UI（Film Atelier 融合，`OpenTalkingAvatar` + `AvatarDock` + global.css）：
   - 相框：hairline 细边框（`--omni-hairline`）、内暗角、左上角 mono 小字状态标
     （连接中 ·/ LIVE · 错误，色随 `--omni-dim`/`--omni-accent`）；speaking 时边框 accent
     微光呼吸（opacity 呼吸 ≤30% 幅度，reducedMotion 关闭）。
   - 字幕区：相框内底部，深色渐变遮罩上 1–2 行字幕，显影渐显（opacity + 轻 blur 过渡，
     ≤300ms）；final 停留 ~2.5s 渐隐；reducedMotion 直接显隐。字幕不得遮挡交互控件。
   - 打断按钮：相框右上角小圆钮（Icon `square` 或 `circle-stop`，lucide），仅 speaking
     可见，`aria-label="打断播报"`，点击调 `interrupt()`，失败静默。
   - 全部视觉 token 走既有 CSS 变量（主题切换自动跟随）；禁止 emoji、禁止新增图标库。

## 四、明确不做（范围护栏）

- **chroma-key 暂缓**：mock 模板视频静态帧无抠像价值，无真实模板视频无法调参验证；
  GPU 节点部署后（M6.4 前后）按真实视频评估。当前形态 = 矩形视频 + Film Atelier 相框。
- **Live2D 字幕不做**：reply 字段已在 statusStore 就位，Live2D 字幕是未来独立小增强。
- **omni_voice 侧不新增工具**：`voice_config` 既有工具已能改配置（执行时确认 tts_muted
  可经其设置；若不能则补 config 写入路径，不新增 tool）。
- 双发声默认不在本期自动切换：交付后由用户 `voice_config` 设 `tts_muted=true`。
